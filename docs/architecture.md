# Архитектура

## Компоненты

```text
 Браузер ──HTTPS:8999*─► kaspersky-vm-metrics.py (Python 3.5+, stdlib, root)
                           ├── StatusCollector ── systemctl show / list-units, ss, /proc
                           ├── RestartManager ─── systemctl restart --no-block
                           ├── RootAuthenticator ─ /etc/shadow | /etc/tcb + crypt(3)
                           ├── логи ───────────── tail -n N -- <файл>, journalctl -u
                           ├── Real-time ──────── tail -n N -F / journalctl -f → Server-Sent Events
                           ├── фоновые задачи ─── отчёт 19:00 (JSON), продление сертификата
                           ├── StateMonitor ───── смена состояний, ОЗУ, диски, ошибки в логах (15 с / 60 с)
                           ├── EventBus ───────── журнал событий (500) → SyslogSender
                           ├── SyslogSender ───── syslog RFC 3164 + CEF → SIEM (TCP/UDP, очередь, повторы)
                           └── watchdog ───────── sd_notify(WATCHDOG=1)
 systemd: kaspersky-vm-metrics.service (Type=simple, WatchdogSec=60, Restart=always)
```

\* 8999 — порт по умолчанию; другой задаётся `install.sh --port N` и хранится в unit-файле (`ExecStart=… --port N`), откуда его читают обновление, откат, `--status` и `--uninstall`.

Сервис — один файл. HTML, CSS и JS встроены в него при сборке (`tools/embed_assets.py`) и отдаются с ETag. Страница загружается один раз, дальше обновляются только данные из `/api/status`.

## Опрос состояния

- Все службы опрашиваются **одним** вызовом `systemctl show`. Результат кэшируется на 1 секунду, так что одновременные клиенты не порождают лишних процессов.
- Время работы службы считается по `ActiveEnterTimestampMonotonic` и не зависит от часового пояса и локали.
- Если учёт памяти в systemd выключен (`MemoryCurrent=[not set]`), память оценивается как сумма VmRSS процессов cgroup.
- Имя службы СУБД ищется раз в 5 минут по маскам `postgresql*.service` и `postgrespro*.service`. Приоритет у работающей службы с процессом: на Debian это `postgresql@NN-main` вместо обёртки `postgresql.service`.
- ОЗУ: используется = MemTotal − MemFree; кэш = Cached + Buffers + SReclaimable; процессы = используется − кэш.
- Загрузка процессора считается по разнице `/proc/stat` между двумя опросами.

## Перезапуск службы

1. Браузер отправляет `POST /api/services/<key>/restart` с паролем root, заголовком `X-Requested-With` и Origin.
2. Сервер проверяет источник запроса, блокировку IP и пароль. Затем выполняет `systemctl restart --no-block <unit>` и отвечает `202`.
3. Пока идёт перезапуск, браузер опрашивает `/api/status` раз в секунду. `RestartManager` считает перезапуск завершённым, когда служба снова активна с новым временем запуска, перешла в `failed` или истекли 180 секунд.

## Логи за день

`GET /logs-today` и `GET /logs-day?date=ГГГГ-ММ-ДД` отдают zip-архив за сегодня или за выбранный прошлый день (будущая или неверная дата — `400 bad_date`). В архив попадают файлы компонентов и их ротированные копии рядом (`<файл>.*`, `<файл>-*`), изменённые в этот день или позже; vms берётся по маске со всеми файлами.

Начало и конец дня в каждом файле находятся двоичным поиском по дате записи: поле `timestamp` в JSON-логах компонентов или дата в начале строки текстового лога. Логи пишутся по порядку времени, поэтому для файла в 150 МБ хватает нескольких десятков чтений. Строки продолжения (стеки исключений) остаются рядом со своей записью. Сжатые копии (`.gz`) читаются последовательно. Если формат даты не распознан, файл включается целиком, когда он изменён в этот день; это отмечается в `README.txt` архива.

Архив собирается во временном файле, одновременно строится только один.

## Real-time

`GET /api/logs/live/<file|journal>/<key>?lines=N` отвечает потоком `text/event-stream`. Сервер запускает `tail -n N -F -- <файл>` (или `journalctl -u <unit> -n N -f`) без оболочки и пересылает вывод событиями:

| Событие | Данные |
|---|---|
| `meta` | вид, ключ, путь к файлу |
| `lines` | массив новых строк (не больше 500 в событии, пачки не чаще раза в 250 мс) |
| `switch` | путь нового файла: для лога vms по маске раз в 5 секунд проверяется, не появился ли более свежий файл |
| `end` | причина: `exited`, `time_limit` (1 час), `server_stopping` |

Раз в 10 секунд уходит пустой комментарий `: ping`. Сокет клиента отслеживается вместе с выводом процесса через `select`: закрытие окна или «Стоп» замечается сразу, процесс завершается, канал закрывается. Одновременно — не больше 8 потоков (`429 too_many_streams`). Браузер после обрыва переподключается с `lines=0`, поэтому строки не повторяются.

## Отчёты о состоянии

`build_state_report()` собирает JSON: свежий опрос служб (без кэша), систему и диски (`statvfs` для `/`, `/var`, `/var/log`, каталогов СУБД и `/opt` без повторов одной ФС), сводку логов за сегодня, события за 24 часа, состояние SIEM и срок сертификата (`openssl x509 -enddate`). Для логов начало дня ищется так же, как для архива, затем просматривается не больше 32 МБ с конца: считаются записи уровней error/warn (поле `level` в JSON или слово уровня в текстовой строке), последние 5 ошибок попадают в отчёт.

Статус: `critical` — не работает хотя бы одна служба; `warning` — ошибки в логах, ОЗУ или диск ≥ 90 %, сертификат истекает через 30 дней; иначе `ok`. Ежедневный отчёт пишется атомарно (временный файл + rename) в 19:00 или при первом запуске после 19:00; `/api/report-now` отдаёт отчёт без записи на диск. Одновременно строится один отчёт.

## События и SIEM

Источники событий: `RestartManager` (запрос, результат перезапуска), обработчики с паролем root (неверный пароль, блокировка, CSRF, изменение настроек), `StateMonitor` (переходы между устойчивыми состояниями служб, рост `NRestarts`, пороги ОЗУ и дисков с гистерезисом 5 п.п., новые записи с ошибками в логах — чтение только дописанных байт, не больше 4 МБ за проход), фоновые задачи (отчёт), `main` (запуск, остановка по SIGTERM).

`SyslogSender` работает в отдельном потоке. TCP: постоянное соединение, LF после каждого события, перед отправкой — проверка, что SIEM не закрыла соединение (`select` + `MSG_PEEK`); подключение идёт под отдельной блокировкой, поэтому недоступная SIEM не задерживает обработчики запросов. Ошибка — событие остаётся первым в очереди, повтор через 1, 2, 4 … 60 с. UDP: датаграмма до 2048 байт. Очередь — 2000 событий, при переполнении отбрасываются самые старые (`dropped`).

## HTTP API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/` | страница; `?lang=ru\|en&theme=dark\|light` |
| GET | `/api/status` | службы, система, порты, `auth.restart`, `siem.state` |
| GET | `/api/report-now` | отчёт о состоянии на текущий момент (JSON-файл) |
| GET | `/api/siem` | настройки, рекомендация (TCP, 5144), счётчики, типы событий, 5 последних событий (`recent`, со статусом доставки и строкой `raw`) и их общее число (`total`) |
| GET | `/api/siem/events?lines=200` | последние события (1–1000, хранится до 500) строками syslog/CEF, от старых к новым |
| POST | `/api/siem` | `{"password", "enabled", "host", "port", "protocol"}` → `200`; ошибки `400 host_required\|bad_host\|bad_port\|bad_protocol`, `500 save_failed` и ошибки проверки пароля |
| POST | `/api/siem/test` | то же тело, тестовое событие без сохранения → `200`; `502 send_failed` |
| POST | `/api/services/<key>/restart` | `{"password": "…"}` → `202`; ошибки: `401 bad_password`, `429 locked`, `403 csrf\|root_locked\|insecure_transport`, `409 in_progress`, `500 systemctl_failed`, `503 auth_unavailable` |
| GET | `/api/logs` | лог-файлы, журналы, отчёты |
| GET | `/api/logs/file/<key>?lines=50` | последние строки файла (1–1000) |
| GET | `/api/logs/journal/<key>?lines=50` | последние строки журнала systemd |
| GET | `/api/logs/live/file/<key>?lines=50` | Real-time: поток SSE новых строк лог-файла; `404 unknown_log\|file_not_found`, `429 too_many_streams` |
| GET | `/api/logs/live/journal/<key>?lines=50` | Real-time: поток SSE журнала systemd |
| GET | `/logs-today`, `/logs-day?date=ГГГГ-ММ-ДД` | zip с логами за сегодня или за выбранный день |
| GET | `/log?file=…`, `/logs-archive?files=[…]` | ежедневные отчёты (JSON) |
| GET | `/brand/<logo\|logo-dark\|logo-light\|favicon>` | логотип и значок вкладки (встроенные или свои из `assets/`) |
| GET | `/healthz` | `{"ok": true, "version": "1.0.0"}` |

Ключи служб: `scanner`, `vms`, `worker`, `privateapi`, `publicapi`, `postgresql`.

## Файлы на сервере

```text
/opt/kaspersky-vm-metrics/
  kaspersky-vm-metrics.py      сервис
  install.sh                   копия установщика (--status, --rollback, --diag, --uninstall)
  KasperskySans-Regular.ttf    шрифт (если был в пакете)
  logo*.svg, favicon.*         свои логотипы вместо встроенного (если были в пакете)
  cert.pem, key.pem            самоподписанный сертификат (создаётся при первом запуске)
  settings.json                настройки отправки в SIEM (права 600; создаётся при сохранении)
  kaspersky-vm-services-state_ДД_ММ_ГГГГ.json  ежедневные отчёты (7 дней)
  backup/<версия>_<дата>/      резервные копии перед обновлением (3 последние)
/etc/systemd/system/kaspersky-vm-metrics.service
```

# Эксплуатация

## Обновление

Новая версия ставится той же командой из её архива, без удаления сервиса:

```bash
scp kaspersky-vm-metrics-<версия>.tar.gz admin@kvm-server:/tmp/
ssh admin@kvm-server
cd /tmp && tar xzf kaspersky-vm-metrics-<версия>.tar.gz && cd kaspersky-vm-metrics-<версия>
sudo bash install.sh
```

Установщик выведет «Обновлено: <старая> → <новая>». Если что-то пойдёт не так, откат выполнится сам; вручную — командой `sudo bash /opt/kaspersky-vm-metrics/install.sh --rollback`.

## Проверка после установки или обновления

```bash
sudo bash /opt/kaspersky-vm-metrics/install.sh --status
systemctl status kaspersky-vm-metrics
journalctl -u kaspersky-vm-metrics -n 50
```

Откройте дашборд и проверьте:

- все службы в статусе «Работает»;
- кнопка «Лог компонента» открывает строки, галочка «Перенос строк» переносит длинные строки, «Real-time лога компонента» показывает новые строки по мере записи;
- «Скачать логи за сегодня» и «Логи за другой день» отдают архив;
- перезапуск некритичной службы (например, publicapi) завершается уведомлением «Служба перезапущена»;
- «Сформировать отчёт сейчас» отдаёт JSON-файл со статусом и списком проблем.

## Отправка событий в SIEM

1. На коллекторе SIEM создайте точку приёма syslog с форматом CEF. Рекомендуется **TCP** и порт **5144** — частый выбор для коллекторов KUMA, потому что порты ниже 1024 (в том числе стандартный 514) требуют на коллекторе дополнительных прав. Подойдёт любой порт, который слушает коллектор.
2. Разрешите исходящие соединения с сервера Kaspersky VM на этот адрес и порт.
3. В дашборде: панель «Отправка событий в SIEM» → «Настроить» → адрес, порт, протокол, пароль root → «Отправить тестовое событие» → «Сохранить».

Состояние отправки видно в панели: «Работает», «Ожидает событий», «Ошибка отправки» с текстом последней ошибки. Пока SIEM недоступна, события копятся в очереди (до 2000) и отправляются после восстановления связи; при UDP доставка не подтверждается.

Настройки хранятся в `/opt/kaspersky-vm-metrics/settings.json` (права 600) и сохраняются при обновлении.

## Типичные ситуации

| Симптом | Причина и решение |
|---|---|
| Кнопка перезапуска сообщает «Для root не задан пароль» | `sudo passwd root` |
| «Сервис работает без HTTPS» | не удалось создать сертификат; проверьте `openssl version` и `journalctl -u kaspersky-vm-metrics` |
| СУБД отмечена «Не установлена» | служба СУБД называется иначе; пришлите вывод `systemctl list-units --all 'postgres*'` |
| В карточке нет кнопки «Лог компонента» | лог-файл не найден: проверьте каталог `/var/log/kaspersky/vulnerability-management/` |
| В архиве за сегодня лог включён целиком (`whole-file` в README.txt) | формат даты в строках не распознан; пришлите первые строки лога |
| Дашборд недоступен из сети | откройте порт сервиса в межсетевом экране; `--preflight` покажет, занят ли порт |
| Порт 8999 занят | `sudo bash install.sh --port <свободный порт>`; проверить заранее: `sudo bash install.sh --preflight --port <порт>` |
| SIEM: «Ошибка отправки», `Connection refused` | коллектор не слушает этот порт или протокол; проверьте точку приёма и протокол (TCP/UDP) |
| SIEM: `timed out` | исходящее соединение блокирует межсетевой экран |
| Тестовое событие по UDP «отправлено», но в SIEM его нет | UDP не подтверждает доставку: проверьте протокол точки приёма или перейдите на TCP |

## Сбор информации для замечаний

```bash
sudo bash /opt/kaspersky-vm-metrics/install.sh --diag
```

Команда создаёт `/tmp/kvm-metrics-diag-<дата>.tar.gz`. В архиве:

- состояние сервиса и служб Kaspersky VM;
- журнал сервиса (1000 строк);
- результат самопроверки;
- список файлов в каталоге логов.

Пароли и закрытый ключ в архив не попадают.

## Замена сертификата

Положите свои `cert.pem` и `key.pem` в `/opt/kaspersky-vm-metrics/` (ключ — с правами 600) и выполните `systemctl restart kaspersky-vm-metrics`. Самоподписанный сертификат пересоздаётся, только если файлов нет или срок их действия истекает в ближайшие 30 дней.

## Чистая переустановка

```bash
cd /tmp/kaspersky-vm-metrics-1.0.0      # каталог распакованного архива
sudo bash install.sh --uninstall --purge
sudo bash install.sh
```

`--purge` удаляет сертификат, отчёты и `settings.json`: браузер один раз попросит принять новый сертификат, настройки SIEM нужно ввести заново. Для обычных обновлений удалять сервис не нужно.

## Удаление

```bash
sudo bash /opt/kaspersky-vm-metrics/install.sh --uninstall           # сертификат, отчёты и settings.json остаются
sudo bash /opt/kaspersky-vm-metrics/install.sh --uninstall --purge   # полностью
```

# kaspersky-vm-metrics
Сервис мониторинга компонентов решения Kaspersky Vulnerability Management

Он показывает состояние служб продукта, потребление памяти и процессора, сетевые соединения и логи. Службы можно перезапускать прямо из браузера после ввода пароля root.

Сервис устанавливается на сервер, где установлен Kaspersky Vulnerability Management одной командой и не требует настройки: службы, СУБД и лог-файлы он находит сам.

## Возможности

- **Службы Kaspersky VM.** Для `scanner`, `vms`, `worker`, `privateapi`, `publicapi` и СУБД показываются состояние, память, PID и время работы. Работает фильтр «Требуют внимания».
- **Перезапуск и запуск служб.** Действие подтверждается паролем root. Карточка показывает ход перезапуска, после завершения приходит уведомление о результате.
- **Логи.** В карточке службы: «Real-time лога компонента», «Лог компонента» (последние 50–1000 строк) и «Журнал службы» (systemd). По умолчанию каждая запись в одну строку, галочка «Перенос строк» переносит длинные строки по ширине окна. Записи с ошибками подсвечены (в том числе JSON-логи компонентов с `"level":"error"`). Поиск по файлу, копирование и скачивание. Архив логов всех компонентов — за сегодня или за любой выбранный день.
- **Real-time.** Новые строки появляются сразу (`tail -f` на сервере, для журнала — `journalctl -f`). Поиск по тексту работает и для новых строк; кнопки «Стоп» и «Продолжить»; после ротации лога vms окно само переключается на новый файл.
- **Сервер.** Загрузка процессора, ОЗУ (процессы + кэш = используется), время работы, сетевые соединения с поиском и сортировкой по столбцам.
- **Отчёты о состоянии в JSON.** Каждый день в 19:00 (хранятся 7 дней) и по кнопке «Сформировать отчёт сейчас». В отчёте: общий статус и список проблем, состояние каждой службы, ОЗУ, процессор, заполнение дисков, число ошибок и предупреждений в логах компонентов за сегодня с последними ошибками, события за сутки, срок действия сертификата.
- **Отправка событий в SIEM.** Достаточно указать адрес и порт: события уходят в формате CEF по syslog. Панель показывает 5 последних событий и обновляется сама; все события — в окне с поиском, переносом строк и скачиванием. Рекомендуются **TCP** и порт **5144** — частый выбор для коллекторов; стандартный порт syslog 514 тоже подходит, если коллектор его слушает. Подробнее — в разделе «[События для SIEM](#события-для-siem)».
- **HTTPS.** Самоподписанный сертификат сервис создаёт и продлевает сам. Сертификат организации ставится одной командой `install.sh --cert … --key …`: установщик проверит его и при проблеме вернёт прежний. Подробнее — в разделе «[Сертификат организации](#сертификат-организации)».
- **Интерфейс:** русский и английский языки, тёмная и светлая темы, автообновление каждые 5–60 секунд. Службы показываются в два ряда по три карточки; раскладка проверена на 10 самых распространённых разрешениях мониторов (от 1280×720 до 3840×2160), на 800×600 и на телефоне.

## Системные требования

Сервис ставится на сервер Kaspersky VM, отдельная машина не нужна.

| | Требование |
|---|---|
| ОС | одна из [поддерживаемых](#поддерживаемые-ос), 64-разрядная: x86_64 или ARM64 (aarch64) |
| Процессор | доли процента одного ядра в среднем; кратко больше при формировании отчёта и просмотре логов |
| Оперативная память | около 30–50 МБ |
| Диск | около 5 МБ в `/opt/kaspersky-vm-metrics`: сервис (~0,4 МБ), до 3 резервных копий, отчёты за 7 дней (по несколько КБ). Журнал сервиса — в journald |
| ПО | systemd; штатный Python 3 из состава ОС (3.5–3.14), только стандартная библиотека — сторонние пакеты не ставятся; `openssl` и `iproute2` (`ss`) — если их нет, установщик поставит из репозитория ОС; `tail`, `journalctl` |
| Права | установка — от root (`sudo`); сервис работает от root, чтобы читать логи и перезапускать службы Kaspersky VM |
| Сеть | входящий TCP 8999 (или порт из `--port`) для браузеров; исходящий TCP или UDP к SIEM, если включена отправка событий (по умолчанию 5144). Доступ в интернет не нужен |
| Учётная запись root | задан пароль (`sudo passwd root`) — нужен для перезапуска служб и настройки SIEM из дашборда |
| Браузер | Chrome / Edge / Яндекс Браузер 111+, Firefox 113+, Safari 16.2+ |

## Установка

1. Скачайте архив `kaspersky-vm-metrics-<версия>.tar.gz` из раздела Releases
2. Скопируйте его на сервер и запустите установщик:

```bash
scp kaspersky-vm-metrics-1.0.0.tar.gz admin@kvm-server:/tmp/

# на сервере
cd /tmp
tar xzf kaspersky-vm-metrics-1.0.0.tar.gz
cd kaspersky-vm-metrics-1.0.0
sudo bash install.sh
```

В конце установщик покажет адрес дашборда: `https://<имя-сервера>:8999/`. Сертификат самоподписанный, поэтому браузер один раз попросит подтвердить исключение.

### Порт сервиса

Указывать порт не обязательно: `sudo bash install.sh` ставит сервис на порт **8999**. Параметр `--port` нужен, только если требуется другой порт — например, 8999 занят или так требуют правила сети:

```bash
sudo bash install.sh --port 9443
```

Проверить заранее, свободен ли порт (команда ничего не меняет):

```bash
sudo bash install.sh --preflight                # порт 8999
sudo bash install.sh --preflight --port 9443    # порт 9443
```

Если порт занят, установщик остановит установку и покажет, какая программа его использует: повторите команду с другим портом.

Порт запоминается: при следующих обновлениях его указывать не нужно. Сменить порт у работающего сервиса можно той же командой с новым номером — установщик проверит, что порт свободен, откроет его в межсетевом экране (firewalld, ufw или iptables) и в SELinux, перезапустит сервис, проверит, что он отвечает на новом порту, и закроет прежний. Если сервис на новом порту не ответит, установщик вернёт прежний порт. Узнать текущий порт: `sudo bash /opt/kaspersky-vm-metrics/install.sh --status`.

Порт должен быть свободен: не выбирайте порты служб Kaspersky VM и СУБД (например, 5432).

Кнопки перезапуска служб работают, только если у root задан пароль. В Ubuntu Server root по умолчанию заблокирован; задать пароль: `sudo passwd root`.

Перед установкой сервер можно проверить командой `sudo bash install.sh --preflight`: она ничего не меняет.

### Сертификат организации

По умолчанию сервис создаёт самоподписанный сертификат и сам продлевает его, поэтому браузер один раз просит подтвердить исключение. Чтобы браузер доверял дашборду без предупреждений, установите сертификат, выпущенный центром сертификации организации:

```bash
sudo bash /opt/kaspersky-vm-metrics/install.sh --cert server.crt --key server.key
```

Если промежуточные сертификаты ЦС лежат в отдельном файле, добавьте `--chain ca-chain.crt`. Ключи можно указать и при первой установке или обновлении из архива: `sudo bash install.sh --cert … --key …`.

Требования к файлам:

- формат PEM (текст `-----BEGIN CERTIFICATE-----`);
- закрытый ключ без пароля: службу запускает systemd, и ввести пароль при старте некому;
- в SAN сертификата есть имя, по которому открывают дашборд (например, `kasperskyvm.sales.lab`).

Установщик сначала проверяет сертификат и ничего не меняет, если он не подходит. Проверяется формат, отсутствие пароля у ключа, что сертификат и ключ из одной пары и что срок не истёк. Если в сертификате нет имени сервера, не хватает промежуточных сертификатов или до конца срока меньше 30 дней, установщик предупредит, но установку продолжит. Затем он кладёт файлы в каталог сервиса (ключ — с правами 600), перезапускает сервис и проверяет, что тот отдаёт именно новый сертификат. Если нет, установщик возвращает прежний.

Сертификат организации сохраняется при обновлениях. Сервис его не продлевает и не заменяет: за 30 дней до окончания срока об этом напомнят баннер в дашборде и ежедневный отчёт. Новый сертификат ставится той же командой. Если файл сертификата повредили вручную, сервис не перейдёт на HTTP: он временно включит запасной самоподписанный сертификат и покажет причину в баннере.

Получить PEM из `.pfx`/`.p12`:

```bash
openssl pkcs12 -in server.pfx -nokeys -out server.crt
openssl pkcs12 -in server.pfx -nocerts -nodes -out server.key
```

Вернуть самоподписанный сертификат: `sudo bash /opt/kaspersky-vm-metrics/install.sh --self-signed`. Какой сертификат используется сейчас, показывает `--status`.

### Чистая переустановка

Если нужно удалить сервис полностью (вместе с сертификатом, отчётами и настройками SIEM) и поставить заново — команды из каталога распакованного архива:

```bash
cd /tmp/kaspersky-vm-metrics-1.0.0
sudo bash install.sh --uninstall --purge
sudo bash install.sh
```

После этого браузер один раз попросит подтвердить новый сертификат. Последующие версии ставятся обычным обновлением, без удаления.

## Использование

### Начало работы

1. Откройте в браузере `https://<имя-сервера>:8999/` (или ваш порт, если он задан через `--port`) и подтвердите исключение для самоподписанного сертификата (один раз).
2. В правом верхнем углу: период автообновления (5–60 секунд или «Выкл.»), кнопка «Обновить сейчас» (клавиша `R`), язык RU/EN и тема. Выбор запоминается в браузере.

### Состояние сервера

- **Сводка** вверху: «Все службы работают» или «Требуют внимания: N из 6», имя сервера, ОС, дата и время на сервере. Если есть проблемы, на значке вкладки браузера появляется цветная точка.
- **Показатели:** запущенные службы, память служб, ОЗУ, загрузка процессора, время работы сервера.
- **Оперативная память:** полоса «Процессы + Кэш + Не используется».

### Службы

Шесть карточек: `scanner`, `vms`, `worker`, `privateapi`, `publicapi` и СУБД. В каждой — состояние («Работает», «Сбой», «Остановлена», «Запускается»…), описание, память, PID и время работы. Переключатель «Требуют внимания» оставляет только службы с проблемами.

Кнопки карточки:

| Кнопка | Что делает |
|---|---|
| «Real-time лога компонента» | новые строки лог-файла в режиме реального времени; у СУБД, у которой нет своего лог-файла, — «Real-time журнала службы» |
| «Лог компонента» | последние 50 строк лог-файла службы |
| «Журнал службы» | журнал systemd службы (`journalctl -u`) |
| «Перезапустить» / «Запустить» | перезапуск или запуск службы; нужен пароль root |
| «Копировать команду перезапуска» | копирует `sudo systemctl restart <служба>` для терминала |

**Перезапуск службы.** Нажмите «Перезапустить», введите пароль root, подтвердите действие. Карточка покажет ход перезапуска, страница будет обновляться раз в секунду, по завершении появится уведомление «Служба перезапущена» или «Служба не запустилась». После пяти неверных паролей за 10 минут ввод с вашего IP-адреса блокируется на 5 минут. Для СУБД окно предупредит, что все службы Kaspersky VM временно потеряют соединение с базой данных.

### Логи

Логи открываются кнопками в карточке службы:

- **«Лог компонента»** и **«Журнал службы»** — последние строки лог-файла или журнала systemd. Количество строк выбирается списком (50–1000). «Поиск по файлу» оставляет только строки с указанным текстом и подсвечивает совпадения. Галочка «Перенос строк» переносит длинные строки по ширине окна, без неё каждая запись занимает одну строку с горизонтальной прокруткой (выбор запоминается). «Обновить», «Копировать», «Скачать .log».
- **«Real-time лога компонента»** — новые строки появляются сразу после записи в файл. Поиск и перенос строк работают и для новых строк. «Стоп» останавливает поток, «Продолжить» возобновляет его без повтора строк, «Очистить» очищает окно, «К новым строкам» прокручивает вниз, если вы листали вверх. Окно хранит последние 5000 строк; одновременно можно открыть до 8 окон Real-time, каждое работает до часа.

Записи с ошибками (`"level":"error"` в JSON-логах, `ERROR`, `FATAL` и т. п. в текстовых) выделены красным, предупреждения — жёлтым.

Над карточками служб — кнопки скачивания:

- **«Скачать логи за сегодня»** — zip-архив с записями всех компонентов за текущий день (для vms — все файлы за день) и `README.txt` со списком файлов.
- **«Логи за другой день»** — выберите день в календаре и нажмите «Скачать архив». В архив попадают записи этого дня из лог-файлов и их ротированных копий рядом (`worker.log.1`, `worker.log-20261105.gz` и т. п.), если они ещё есть на сервере.

### Отчёты о состоянии

- Ежедневный отчёт в JSON формируется в 19:00 и хранится 7 дней. Отметьте отчёты галочками и нажмите «Скачать» (несколько — одним zip-архивом).
- «Сформировать отчёт сейчас» — отчёт на текущий момент, скачивается сразу.
- В отчёте: общий статус (`ok`, `warning`, `critical`) и список проблем, состояние каждой службы, ОЗУ, процессор, заполнение дисков, ошибки и предупреждения в логах за сегодня с последними ошибками, события за сутки, состояние отправки в SIEM, срок действия сертификата.

### Отправка событий в SIEM

1. Панель «Отправка событий в SIEM» → «Настроить».
2. Укажите адрес SIEM-системы и порт. Рекомендуемые значения выделены: **TCP**, порт **5144**.
3. Введите пароль root, нажмите «Отправить тестовое событие» и проверьте его в SIEM.
4. Нажмите «Сохранить». Панель покажет состояние («Работает», «Ожидает событий», «Ошибка отправки»), счётчики и 5 последних событий. Панель обновляется вместе с остальным дашбордом (интервал в правом верхнем углу), перезагружать страницу не нужно.
5. Каждое событие раскрывается: название, ID, важность, статус доставки («отправлено», «в очереди», «не отправлено») и строка syslog/CEF ровно в том виде, в каком она уходит в SIEM, — с кнопкой копирования. Галочка «Перенос строк» переносит длинные строки вместо горизонтальной прокрутки.
6. «Все события» открывает окно, как у логов: последние 50–500 событий строками syslog/CEF, «Поиск по событиям», «Перенос строк», «Копировать», «Скачать .log». События с важностью 4–5 подсвечены красным, 3 — жёлтым. Новые события появляются в окне сами.

Чтобы выключить отправку, снимите галочку «Отправлять события в SIEM» и сохраните. Список событий — в разделе «[События для SIEM](#события-для-siem)».

### Статус соединений

Раскрывающаяся панель внизу: открытые порты сервера (`ss -tulnp`), процесс и служба Kaspersky VM. Есть поиск по порту, адресу и процессу, фильтр «Только службы Kaspersky VM» и сортировка по любому столбцу.

### Если что-то не так

| Симптом | Что сделать |
|---|---|
| Кнопка перезапуска сообщает, что для root не задан пароль | `sudo passwd root` |
| «Сервис работает без HTTPS» | не удалось создать сертификат: `openssl version`, `journalctl -u kaspersky-vm-metrics` |
| СУБД «Не установлена» | служба СУБД называется иначе: `systemctl list-units --all 'postgres*'` |
| В карточке нет кнопки «Лог компонента» | лог-файл не найден: проверьте каталог `/var/log/kaspersky/vulnerability-management/` |
| Дашборд недоступен из сети | откройте порт сервиса (8999/tcp или заданный через `--port`) в межсетевом экране |
| Порт 8999 занят другой программой | установите сервис на другой порт: `sudo bash install.sh --port 9443` |
| SIEM: «Ошибка отправки» | проверьте адрес, порт и протокол точки приёма в SIEM и межсетевой экран |

## Обновление

Обновление выполняется той же командой из архива новой версии. Удалять установленную версию не нужно:

```bash
tar xzf kaspersky-vm-metrics-1.1.0.tar.gz && cd kaspersky-vm-metrics-1.1.0
sudo bash install.sh
```

Установщик выполняет следующие шаги:

1. Проверяет контрольные суммы архива.
2. Проверяет, что новая версия запускается на этом сервере. Пока это не подтверждено, ничего не меняется.
3. Сохраняет резервную копию текущей версии (хранятся три последние).
4. Заменяет файлы атомарно и перезапускает службу. Перерыв занимает 1–2 секунды; открытые дашборды переподключаются и перезагружаются сами.
5. Проверяет, что новая версия отвечает. Если нет — автоматически возвращает предыдущую.

Сертификат, отчёты и настройки SIEM (`settings.json`) при обновлении сохраняются.

Если номер версии не изменился (повторная установка той же сборки), добавьте `--force`: `sudo bash install.sh --force`. Порт, заданный через `--port`, сохраняется при любом обновлении.

## Что сервис находит сам

| Объект | Как определяется |
|---|---|
| Службы Kaspersky VM | `kaspersky-vm-{scanner,vms,worker,privateapi,publicapi}.service` |
| СУБД | первая работающая из `postgresql*.service`, `postgrespro*.service` (например, `postgresql-15`, `postgresql@15-main`); проверка повторяется раз в 5 минут |
| Логи | `/var/log/kaspersky/vulnerability-management/<служба>/<служба>.log`; для vms — самый свежий `vms/vms_<дата-время>.log` |

Лог читается на сервере командой `tail -n <N> -- <файл>`. Если сервис запущен не от root, используется `sudo -n`. Команда выполняется без оболочки, а путь к файлу задаётся в коде и не принимается из запроса.

## События для SIEM

Настройка: панель «Отправка событий в SIEM» → «Настроить». Укажите адрес и порт коллектора, выберите протокол, введите пароль root. Кнопка «Отправить тестовое событие» проверяет связь до сохранения настроек.

| | Рекомендуется | Допустимо |
|---|---|---|
| Протокол | **TCP** подтверждает доставку и не обрезает длинные события; пока SIEM недоступна, события копятся в очереди (до 2000) | UDP: без подтверждения доставки, события длиннее 2048 байт обрезаются |
| Порт | **5144**: частый выбор для коллекторов (порты ниже 1024 требуют на коллекторе дополнительных прав) | 514: стандартный порт syslog, или любой порт, который слушает коллектор CEF по syslog |

Формат: syslog RFC 3164 (facility `local0`), сообщение — `CEF:0|Kaspersky|Kaspersky VM Metrics|1.0.0|<ID>|<название>|<важность>|...`. По TCP каждое событие — одна строка. Пробелы везде одиночные: в дате (`Nov 6 12:04:19`) и в значениях — табуляции, переводы строк и повторяющиеся пробелы из логов компонентов заменяются одним пробелом.

Важность — от 1 до 5: 1 — информация, 2 — низкая, 3 — средняя, 4 — высокая, 5 — критическая.

| ID | Событие | Важность |
|---|---|---|
| 100 / 101 | сервис мониторинга запущен / остановлен | 1 / 2 |
| 200 / 201 / 202 | служба заработала / остановилась / завершилась сбоем | 1 / 4 / 5 |
| 203 | systemd перезапустил службу после сбоя | 3 |
| 210 / 211 / 212 / 213 | перезапуск из дашборда: запрошен / выполнен / не удался / не завершился за 3 минуты | 2 / 1 / 4 / 4 |
| 300 / 301 / 302 | неверный пароль root / IP заблокирован / запрос с чужого источника | 3 / 4 / 4 |
| 310 | изменены настройки отправки в SIEM | 3 |
| 400 / 401 | занято ≥ 90 % ОЗУ / норма | 3 / 1 |
| 402 / 403 | файловая система заполнена на ≥ 90 % / норма | 4 / 1 |
| 500 | новые записи с ошибками в логе компонента (не чаще раза в минуту на файл) | 3 |
| 600 | сформирован ежедневный отчёт | 1 |
| 900 | тестовое событие | 1 |

Поля расширения: `rt`, `dvchost`, `cat`, `msg`, `src` (IP клиента), `suser`, `act`, `outcome`, `filePath`, `cnt`, `cs1` — unit, `cs2` — состояние, `cs3` — компонент, `cs4` — путь, `cs5` — адрес SIEM, `cfp1` — процент.

## Безопасность

- Пароль root проверяется по `/etc/shadow` (`/etc/tcb` на Альт) через системный crypt(3). Он нужен для перезапуска служб, изменения настроек SIEM и отправки тестового события. После 5 ошибок за 10 минут IP-адрес блокируется на 5 минут. Каждое такое действие записывается в журнал (`journalctl -u kaspersky-vm-metrics | grep AUDIT`) и отправляется в SIEM, если отправка включена.
- Если HTTPS не поднялся, пароль root не принимается.

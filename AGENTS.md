# Kaspersky VM Metrics · план испытаний версии 1.1.0

## Что входит в версию

База сравнения — версия `1.0.0`, коммит `f410f50`. Релиз `1.1.0` включает перенос на Go из ветки `feature/go-1.2`, коммит `52f25aa` (тестовая сборка `1.2.0-dev`). Сервис и установщик собираются в один Linux ELF. Штатная команда `sudo bash install.sh` проверяет контрольную сумму бинарника из пакета и передаёт ему аргументы. Веб-страница, таблицы стилей, сценарии браузера и логотип входят в бинарник через `go:embed`. Шрифт и пользовательские изображения по-прежнему можно разместить рядом с программой.

Два осознанных изменения поведения важны при испытаниях. В отладочном режиме `--no-tls` административные POST-запросы возвращают `403 insecure_transport`. При подключении сертификата организации установщик проверяет отпечаток сертификата, который действительно предъявляет служба. Если подтвердить отпечаток не удаётся, установщик восстанавливает прежнюю пару.

## Воспроизведение

Из корня проекта на Linux с Go 1.23+ и C-компилятором выполните следующие команды. Cgo загружает системную `libcrypt` для проверки shadow-хешей, включая формат, выбранный дистрибутивом. При отсутствии библиотеки мониторинг работает, а защищённые операции возвращают `auth_unavailable`.

```bash
make vet test
go tool cover -func=coverage.out
go tool cover -html=coverage.out -o /tmp/kvm-coverage.html
make package
bash tools/smoke-package.sh dist/*-linux-$(go env GOARCH).tar.gz
```

`make test` запускает тесты с детектором гонок. Достаточно непривилегированного пользователя. Тесты создают временные каталоги, слушают loopback, используют синтетический shadow-файл и подменяют команды управления службами. Проверка `TestLocalCrypt` использует известную строку с тестовым паролем. Данные продуктивного сервера для прогона не требуются.

Из Git-клона запустите `make test-upgrade` для проверки совместимости. Тест извлекает исходную 1.0.0 из коммита `f410f50`, запускает её по HTTPS, обновляет тот же каталог до Go-версии и выполняет откат. Сравниваются значения метрик шести служб, порты, ресурсы интерфейса и хеши файлов с данными. Второй сценарий собирает тестовую версию из коммита `52f25aa`. При переходе с `1.2.0-dev` на `1.1.0` он проверяет отказ без `--force`, затем установку с `--force` и откат к исходной сборке. Для этих сценариев на машине тестирования нужны Git, Python 3 и OpenSSL. Для эксплуатации готового пакета достаточно его Linux-бинарника и системных утилит из README.

Для сквозной проверки интерфейса укажите путь к Chromium в `KVM_BROWSER`. Для обязательной проверки транспорта уведомлений systemd задайте `KVM_REQUIRE_UNIXGRAM=1`. Порт пакетной проверки по умолчанию 18999, переопределение — `SMOKE_PORT`. Пакет предназначен для архитектуры в имени файла.

```bash
KVM_BROWSER="$(command -v google-chrome)" go test -count=1 -v -run TestDashboardBrowser .
KVM_REQUIRE_UNIXGRAM=1 go test -count=1 -v -run TestSystemdUnixgram .
```

## Проверка обновления до 1.1.0

На Linux amd64 проверены переходы `1.0.0 → 1.1.0 → 1.0.0` и `1.2.0-dev → 1.1.0 → 1.2.0-dev`. В обоих случаях реальные процессы последовательно отвечали по HTTPS на прежнем порту. Контрольные суммы сертификата, ключа, маркера УЦ, настроек SIEM и отчёта совпали после перехода и после отката. Обе проверки входят в `make test-upgrade` и выполняются также на нативных amd64 и arm64 в CI.

Локальная среда запрещает создание Unix-сокетов, которые используют Chromium и systemd. Эти две проверки прошли на Linux-узлах GitHub. CI измеряет покрытие в основном прогоне. Переход с Python и отрисовку в Chromium проверяет отдельно.

Для проверки на тестовой ВМ с systemd выполните `bash tools/smoke-systemd.sh build/$(go env GOARCH)/kaspersky-vm-metrics`. Сценарий создаёт временный unit через `sudo -n systemd-run`. Сервис работает от имени текущего пользователя на loopback-порту 18998. Тест проверяет смену состояния на active, версию по HTTPS, обновление отметки watchdog и остановку unit. Порт можно изменить через `SMOKE_PORT`.

Для воспроизведения полного измерения на нативной архитектуре выполните команды ниже.

```bash
make build
KVM_UPGRADE_BINARY="$PWD/build/$(go env GOARCH)/kaspersky-vm-metrics" \
  go test -race -count=1 -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
```

## Выпуск

Номер версии берётся из `VERSION`. Публикация запускается при попадании в `main` коммита с заголовком `Release v1.1.0` для этой версии. GitHub Actions проверяет код, оба маршрута обновления, штатный systemd и запуск упакованных бинарников на нативных amd64 и arm64. Затем он прикрепляет оба проверенных архива и общий `SHA256SUMS`, сверяет загрузку и публикует тег на том же коммите.

Внутри каждого архива находятся бинарник своей архитектуры, шрифт, `install.sh`, `README.md`, `AGENTS.md`, `VERSION` и контрольные суммы содержимого. Результаты автоматических проверок доступны по ссылке в [релизе 1.1.0](https://github.com/vda23/kaspersky-vm-metrics/releases/tag/v1.1.0). Проверки на действующей установке Kaspersky VM с PostgreSQL, приём событий в KUMA и 24-часовой нагрузочный прогон остаются в плане стендовых испытаний.
